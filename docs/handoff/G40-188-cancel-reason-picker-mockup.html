3 · Gopher cancels a scheduled request

This one already asks for a reason. The problem is the shape of the answer.

Current

Cancel Request

Must be at least 3 words. This will be shared with the Requestor and eligible for a rating so please be professional and clear.

What happens today
  • Free text, minimum 3 words, 150 characters — every worker phrases it differently.
  • cxRecommend() must tokenise that prose to suggest fee / no-fee / excused. It is guarding a $5 charge and a strike.
  • ⚠️ A second door bypasses this entirely: requestOrder.js:423 in the Go app fires DELETE orders/:id with no reason.
  • Live typo in the counter: “Max charactors reached”.
Proposed
Scheduled job

Cancel this job?

Your answer is shared with the Requestor and is used when a cancellation is reviewed. Pick the closest match.

0 / 150
What changes
  • Seven options, not six — the extra precision is worth it where money is at stake.
  • 1, 3, 6 read as presumptively excused. 4, 5 point at the requester or the listing, not the worker. 2, 7 are the real review cases.
  • ⚠️ A recommendation to the reviewer, never an automatic outcome — otherwise “Emergency or illness” becomes the button everyone learns to press.
  • 3-word minimum survives, applied only to “Other”. Typo fixed.

What I would change in code

  • Requester app — requestOrder.js onTappedCancel() opens the sheet and sends cancellation_reason; it currently sends an empty body.
  • Go app — ordercard.js swaps the textarea for the picker, and requestOrder.js:423’s reason-less cancel routes through the same sheet or loses its button.
  • Shared component — modals/CancelRequestReasonModal.js already exists in the Go app and is imported by nothing. It becomes the one implementation rather than a third.
  • Backend — nothing. cancellation_reason already persists and the email already renders it.

Two traps this design is built around

  • ⚠️ Keyboard occlusion. A textarea at the bottom of a sheet is the exact shape of G40-421 — already open, ten instances. “Other” reveals the field above the buttons and the sheet scrolls; it should still land on whatever shared fix 421 produces.
  • ⚠️ Fixed bottom controls covering content is the pattern behind G40-422/423/424 — four screens, both apps. The option list scrolls inside the sheet; the buttons never overlay it.

Not decided here
