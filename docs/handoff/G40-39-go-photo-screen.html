Skip the photo?
If you left this delivery unattended, the photo is your proof it arrived. Without it you have nothing to point to if the customer says it never showed up.
Skip anyway

Only fires when the server (or the category-type fallback) says the order is a Delivery. "Take a photo" is deliberately the easy, primary button — the friction is the point, so the button roles are never swapped. Copy is server-served (photo_requirement.skip_warning); this is the bundled fallback, which is what renders on an older backend response.

What determines whether this screen appears at all

ordercard.js routes here only when photo_requirement.applies (server) or, absent that field, !age_restricted? (client fallback) — see the memory of this session for the full trace. If neither condition holds, or if the Gopher's app build predates c6afb936e (2026-08-20), this screen is never reached and the flow goes straight to the waiting screen instead.
