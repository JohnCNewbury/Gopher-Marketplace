# G40-450 — the 101-guide half, and why it is a patch instead of an edit

**Status: PREPARED, DELIBERATELY NOT APPLIED. Apply when the store build ships, not before.**

Owner rule (standing rules §5): *a user-facing change is not done until its 101 guide is updated.*
G40-450 adds a visible **↻ Refresh** control to the Gopher Available list (plus pull-to-refresh) and
to both requester surfaces. That is user-facing, so the guides owe an update.

## ⛔ Why it is not applied yet

The other half of the same rule is the honesty standard from the June `gopher-request.html` copy
work: **the guide describes what the product does, not what it will do.**

The control does not exist on anybody's phone. There is no OTA path in either mobile repo — Appflow
Live Updates is not enabled — so it reaches users **only through a store release**. Writing it into
the live 101s now would tell a real worker to look for a button that is not there, on the exact
screen this ticket is about. That is worse than saying nothing.

## ⛔ Why it is a patch file and not an uncommitted edit

`scripts/deploy.sh` reads the **working tree** and ships the whole of `Final/`. An uncommitted edit
sitting in `Final/gopher-go-101.html` is published by the next `--allow-dirty` run by *any* session
(standing rules §3 — "committed but not deployed" is not a durable state, and neither is
"uncommitted but nobody will deploy today"). A patch under `docs/handoff/` is outside `Final/` and
cannot ride along.

## What it says

Two `note info` blocks, one per guide, no other change:

- **`Final/gopher-go-101.html`** — *"Heard the alert but don't see the job?"* Pull down, or tap
  ↻ Refresh. Says plainly that the list already checks every few seconds and that **closing and
  reopening the app should never be necessary** — which is the belief this whole ticket exists to
  undo.
- **`Final/gopher-request-101.html`** — *"Something looks out of date?"* Refresh on the request list
  and on the request itself, same reassurance.

Both are deliberately short and both are true **only after the store build**.

## How to apply

```bash
git apply docs/handoff/G40-450-101-guides.patch
```

Then deploy `Final/` as normal, and delete this file and the patch — a prepared change that has been
applied is just clutter that reads as pending.

⚠️ If the guides have moved on before then, `git apply` will reject. Re-read the surrounding copy
rather than forcing it: standing rules §5 exists because a minimal find-and-replace on the Deals 101
is what created that rule in the first place.
