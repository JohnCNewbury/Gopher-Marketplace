You said the navy ink read as more readable, but not more crisp — and you were right, for a reason that was my fault: that page set -webkit-font-smoothing:antialiased on its body, so both panels already had the smoothing correction applied. The only variable left was ink colour, which buys contrast, not edge definition. It couldn't have shown you crispness either way.

This page fixes that. It renders at font-smoothing:auto — what the live dashboards actually use — and each strip below changes exactly one thing. Ink colour is not a variable here.

The pulsing attention glow is not in this test and is not on the table. You're right that it was never the issue — and it couldn't have been: a non-inset box-shadow paints outside the button, behind an opaque fill, so it never touches the letters. The words inside that button are a real problem, but it's their ink colour, which is the separate fix.
