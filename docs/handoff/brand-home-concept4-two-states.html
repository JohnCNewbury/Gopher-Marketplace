Gopher Request · home · concept 4, your model

Cards lead. Activity slides them down — by a fixed amount.

The two cards are the home screen. When there's activity it appears above them in one bounded container, ported from the prototype's #hubSlot — real buckets, counts in the tabs, alert dot on anything needing your action. Messages is the fourth segment, and cards show 2-up instead of a carousel since this is 1200px not a phone. Because the container's height doesn't grow with the number of requests, the cards sit at a predictable depth however busy the user is — which is what buys the room to make them bigger. Nothing is implemented.

State A · quiet

Nothing live — the cards are the whole screen

No activity in any bucket, so the container isn't rendered at all (the prototype hides it when Active + Scheduled + Submitted are zero). The cards get the full canvas and a real hero treatment. The sidebar's + New Request and Deals buttons stay hidden here — they'd duplicate what the user is looking at, which is the rule your code already states.

State B · busy

Four live things — cards slide down once, and stop

Two active, one scheduled, one submitted, three unread. The container takes a fixed ~200px whether that's four items or forty — a fifth request adds a dot, not height. The cards are still fully visible and still substantial. Submitted carries the alert dot (a counter-offer is waiting) so it's visible from the Active tab. And the sidebar CTAs appear here, because the cards are no longer the first thing on screen.

The cards shrink, they don't disappear — shorter copy, tighter padding, same shape and same CTAs. A returning user still recognises the screen they learned on. That's the part worth checking with your own eye: whether they shrink too much, or not enough.

Nothing here is implemented. Two things I decided while building and would flag rather than bury: the busy state's headline changes from "So, how can we help you today?" to "Here's what's live right now", because asking how it can help while the user's couch is in transit reads oddly — and the Dashboard nav item disappears in both states, since merging the chooser into the dashboard leaves it pointing at the screen you're already on. Its badge count moves into the segment tabs, which is arguably where it belonged.
