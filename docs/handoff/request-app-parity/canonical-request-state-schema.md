# Canonical Request State Schema — the cross-platform contract

**Why this exists.** Gopher Request (web) and the Gopher Request App are one product on two
platforms. A request must be **portable**: start it on the app, finish it on the web, lose
nothing. That only works if a request is *one well-defined, serializable object* that any
platform can rehydrate. This document is that contract — the single source of truth for what a
request *is*, independent of UI.

It also feeds the dev handoff: build persistence + native UI against **this schema**, not against
whichever HTML file you happened to open. It is deliverable #1 of the Request-app consolidation
(see `parity-harness` and the shared-logic modules for #2/#3).

Generated by comparing `makeInitialState()` across the three current surfaces:
`_prototypes/Request/gopher-request-flow.html` (P), `Final/gopher-request.html` (R),
`Final/gopher-connect.html` (C). **77 distinct fields; 42 identical across all three; 35 drift.**

---

## 1. The split that matters: persisted contract vs. transient UI

Only the **persisted contract** must be identical across platforms — it is the resume payload the
backend stores and any platform rehydrates. **Transient UI state** (which accordion is open, is the
payment picker dropped down) is legitimately per-platform and is NEVER persisted or transferred.

- **Persisted contract** → the request *data*: category, description, delivery-type flags, item/rider
  detail, worker plan, locations, pay, schedule, promo/payment selection, age-restricted resolution.
- **Transient (do NOT persist):** `openInfo`, `openCatInfo`, `osOpen`, `paymentPickerOpen`,
  `sseOpen`, `wteOpen`, `profileOpen`, `calViewISO`, `*PickerOpen`, `*Prompted`, `*Ack`/`*Dismissed`
  (backstop-suppression flags — re-derive per session).

The resume rule: **persist the contract, drop the transient, re-run the gates on rehydrate.** If a
user resolved the age prompt on the app, that's captured by `ageRestricted` (contract), not by
`ageKeywordAck` (transient) — the web re-derives the prompt from the description + `ageRestricted`.

## 3. Drift — must be reconciled to one canonical shape

Ordered by severity. **These are the concrete things that break "resume where you left off."**

### 3a. STRUCTURAL — same concept, different shape (HIGH — breaks rehydrate)

> **✅ RECONCILED 2026-07-14.** The prototype was migrated to the canonical shapes below;
> the parity harness now enforces a **50-field universal core** (the original 42 + the
> location arrays + the §3b contract fields) and treats any reappearance of the retired
> shapes (`pickupStop`/`dropoffStop` strings, `idVerified` bool) as new drift.

| Concept | Prototype (P) — retired | Canonical (all surfaces) | Resolution |
|---|---|---|---|
| Pickup location | `pickupStop` *(string)* | `pickupStops` *(array)* | Migrated: init/inputs/reads/submit use the array (single-stop UI reads/writes element 0 via `pickupAddr()`); binder writes `[value]`. |
| Drop-off location | `dropoffStop` *(string)* | `dropoffStops` *(array)* | Same, via `dropoffAddr()`. |
| ID verification | `idVerified` *(bool)* | `idFrontCaptured`, `idFrontSrc`, `selfieCaptured`, `selfieSrc`, `savedOnFile` | Migrated: "verified" is **derived** (`savedOnFile || (idFrontCaptured && selfieCaptured)`, helper `idVerifiedNow()`); writes go through `markIdVerified(onFile)`. |

### 3b. CONTRACT GAPS — a real data field missing on a surface (MED — add it)

| Field | Present | Missing | Note |

### 3c. PLATFORM-SPECIFIC — legitimately not universal (LOW — document, don't force)

- **Deal provenance** (`fromDeal`, `dealKind`, `dealBoost`) — R only. A request *can* originate from a
  Deal on any platform, so these belong in the contract; add to P/C when those platforms support Deals.
- **Connect business** (`businessPlan`, `eligibleWorkers`, `laborManagement`) — C only. These are
  Connect-business features; keep out of the consumer Request contract unless the app adds business mode.
- **Backstop-suppression / UI** (`dupWarnAck`, `lowAvailabilityAck`, `waiverPrompted`, `hireAgainGophers`,
  `submittedAt`, `profileOpen`, `openInfo`, `openCatInfo`, `osOpen`) — transient; re-derive per session.

## 4. What the dev builds against

1. **One `RequestState` type** = §2 core + §3a canonical shapes + §3b fields, minus the §1 transient set.
2. **Persistence** stores that object; **rehydrate** restores it and re-runs the step gates
   (age-restricted, category-mismatch, low-offer, duplicate, availability) — see the shared-logic
   modules — so the resumed request is validated identically to a fresh one.
3. **Location shape = arrays** (`pickupStops`/`dropoffStops`); ID = Final's capture object.
