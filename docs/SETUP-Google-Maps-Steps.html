Google Maps setup — Gopher Deals audience map

Everything below is the by-hand work I couldn't do from your machine: the Google Cloud console, pasting the key, and uploading two files. No backend, no database — the page runs on the Google Maps API alone.

Page: Final/gopher-deals.html  ·  Live URL: https://gophergo.io.customers.tigertech.net/preview/gopher-deals.html  ·  Google project: gopher-inc
What the map does now. Typing an address uses Google Places Autocomplete (the dropdown) and Geocoding (address → location). The dots and counts come from a privacy-safe local dataset baked into the site (assets/js/gopher-deals-audience.js) — ZIP-area points with jitter, no real home addresses, no live data calls. So the only thing you switch on is Google Maps.

Part A — Google Cloud console project: gopher-inc

Console: https://console.cloud.google.com

  1. Select the project. Top bar → project picker → choose gopher-inc. Confirm it shows in the header before continuing.
  2. Enable the three APIs. Go to APIs & Services → Library (or the Google Maps Platform → APIs page) and enable each one:
    Maps JavaScript API
    the visible map
    Places API
    the address autocomplete dropdown
    Geocoding API
    typed address → coordinates
  3. Create a browser API key. APIs & Services → Credentials → Create credentials → API key. A key string appears — leave the dialog open for the next step.
  4. Restrict the key — application (referrers). Edit the key → Application restrictions → HTTP referrers (web sites) → add exactly these (the * matters): 
    https://gophergo.io.customers.tigertech.net/*
https://gophergo.io.customers.tigertech.net/preview/*
http://localhost:*/*
http://127.0.0.1:*/*
    (The two localhost lines are only for local testing — you can remove them once it's live.)
  5. Restrict the key — API restrictions. Same page → API restrictions → Restrict key → tick only Maps JavaScript API, Places API, and Geocoding API. Save.
  6. Set a budget + quota cap (a public key should never be able to run up a surprise bill):
    • Billing → Budgets & alerts → create a budget (e.g. $25/mo) with email alerts at 50/90/100%.
    • APIs & Services → each of the three APIs → Quotas → set a low daily request cap (e.g. a few thousand/day) so a runaway can't blow past your budget.
  7. Copy the key. You'll paste it in Part B.
Rough cost. Maps loads ≈ $7 / 1,000; Geocoding & Places ≈ $5 / 1,000. A full "type + pick a suggestion" counts as one Places session (session tokens are automatic), not one call per keystroke. Google's monthly free tier covers light traffic.

Part B — Put the key in the site

  1. Open Final/gopher-deals.html.
  2. Find the Google Maps loader near the end of the <head> (around line 2955) — it's the only line with maps.googleapis.com: 
    <script async
  src="https://maps.googleapis.com/maps/api/js?key=YOUR_NEW_BROWSER_KEY&libraries=places&callback=onGopherMapsReady&loading=async"></script>
  3. Replace YOUR_NEW_BROWSER_KEY with the key you copied. Change nothing else on that line (keep &libraries=places, &callback=onGopherMapsReady, &loading=async). Save.

Part C — Upload to the preview host

TigerTech preview at gophergo.io.customers.tigertech.net/preview/

  1. Upload two files, keeping the folder path exactly so the page can find its dataset:
    The page
    gopher-deals.html → /preview/gopher-deals.html
    The audience data
    assets/js/gopher-deals-audience.js → /preview/assets/js/gopher-deals-audience.js
    The dataset file is ~0.6 MB. If the page shows a map but no dots, this file didn't upload or landed at the wrong path — see troubleshooting.
  2. That's the whole deploy. There is no backend, no database migration, and nothing for Rob to push through CodePipeline / Elastic Beanstalk for this page.

Part D — Verify end to end

  1. Load https://gophergo.io.customers.tigertech.net/preview/gopher-deals.html.
  2. Type an address in the audience box — a suggestions dropdown should appear as you type (that's Places working).
  3. Pick a suggestion (or press Enter) — the overlay opens and the Google map renders with a green radius ring and a navy center pin.
  4. Check the dots & counts — green = customers nearby, navy = workers (Gophers) nearby, with live "customers / workers / total" numbers.
  5. Drag the radius slider — the ring grows and the counts update instantly (no lag, no extra Google calls — filtering is local).
  6. After testing, check billing/quota in the console to confirm usage looks sane.

Troubleshooting

Blank / grey map → the key is missing, wrong, or the referrer restriction doesn't include this domain. Recheck Part A step 4 and Part B. Browser DevTools → Console will say RefererNotAllowedMapError or InvalidKeyMapError.
No address suggestions → the Places API isn't enabled, or isn't allowed on the key (Part A steps 2 & 5).
Map shows but no dots / counts stay 0 → the dataset file didn't upload or is at the wrong path. Open DevTools → Network and look for a 404 on assets/js/gopher-deals-audience.js. It must sit at /preview/assets/js/gopher-deals-audience.js.
Address won't resolve → the Geocoding API isn't enabled/allowed on the key. The box will say "we couldn't find that address."

No credentials are stored in this file. Keep your API key out of email/chat — paste it only into the site file in Part B.
